# โครงสร้างในหน่วยความจำ

กุญแจสำคัญในการออกแบบรอบนี้ของเราคือชนิดข้อมูล `RefCell` โดยหัวใจหลักของ `RefCell` นั้นอยู่ที่เมธอดคู่หูสองตัวนี้:

```rust ,ignore
fn borrow(&self) -> Ref<'_, T>;
fn borrow_mut(&self) -> RefMut<'_, T>;
```

กฎการใช้งานของ `borrow` และ `borrow_mut` นั้นเหมือนกับกฎของ `&` และ `&mut` ทุกกระเบียดนิ้ว: คุณสามารถเรียก `borrow` ซ้ำกี่ครั้งก็ได้ตามใจชอบ แต่การเรียก `borrow_mut` จะต้องไม่มีใครอื่นถือเรเฟอเรนซ์ค้างอยู่เลย (exclusivity)

แต่แทนที่คอมไพเลอร์จะตรวจสอบและบังคับใช้กฎนี้แบบสแตติกตอนคอมไพล์ เจ้า `RefCell` กลับเลือกที่จะตรวจสอบกฎเหล่านี้ตอนรันไทม์ (runtime) แทน! และถ้าคุณแอบฝ่าฝืนกฎเหล่านั้น `RefCell` ก็จะสั่ง panic แล้วแครชโปรแกรมทิ้งทันที! แล้วทำไมมันต้องคืนค่าเป็นพวก `Ref` กับ `RefMut` ออกมาด้วยล่ะ? จริง ๆ แล้วชนิดข้อมูลพวกนี้ทำหน้าที่คล้ายกับ `Rc` แต่ใช้สำหรับการยืม (borrowing) โดยพวกมันจะช่วยล็อกให้ `RefCell` คงสถานะการถูกยืมเอาไว้จนกว่าตัวมันเองจะหลุดออกจากสโคป ซึ่งเดี๋ยวเราจะมาเจาะลึกเรื่องนี้กันต่อ

ทีนี้เมื่อเรามีทั้ง `Rc` และ `RefCell` ร่วมกัน เราก็พร้อมที่จะแปลงร่างกลายเป็น... ภาษาเขียนโปรแกรมที่โค้ดเวิ่นเว้อยืดยาว มีการแก้ไขค่าแทรกซึมอยู่ทุกหนทุกแห่ง มีระบบเก็บขยะ (GC) แต่ดันเก็บขยะที่เป็นวงรอบ (cycles) ไม่ได้! ยะ... เย้... ชะ... ไชโย... (Y-yaaaaay...)

เอาล่ะ เราต้องการสร้างเดกแบบ *เชื่อมโยงสองทาง (doubly-linked)* นั่นแปลว่าในแต่ละโหนดจะต้องมีตัวชี้ชี้ไปยังโหนดก่อนหน้า (prev) และโหนดถัดไป (next) นอกจากนี้ตัวลิสต์เองก็จะมีตัวชี้ชี้ไปยังโหนดแรก (head) และโหนดสุดท้าย (tail) ด้วย ซึ่งจะเปิดทางให้เราสามารถแทรกและลบข้อมูลที่ปลาย *ทั้งสองฝั่ง* ของลิสต์ได้อย่างรวดเร็วระดับ O(1)

ดังนั้นโครงสร้างที่เราต้องการก็น่าจะมีหน้าตาประมาณนี้:

```rust ,ignore
use std::rc::Rc;
use std::cell::RefCell;

pub struct List<T> {
    head: Link<T>,
    tail: Link<T>,
}

type Link<T> = Option<Rc<RefCell<Node<T>>>>;

struct Node<T> {
    elem: T,
    next: Link<T>,
    prev: Link<T>,
}
```
