# เดก (Deque) สองทางแบบ unsafe คุณภาพระดับโปรดักชัน

ในที่สุดเราก็มาถึงแล้ว ศัตรูตัวฉกาจที่สุดของข้า: **[std::collections::LinkedList][linked-list] เดก (Deque) สองทาง**

ตัวที่ข้าพยายามจะทำลายแต่ทำไม่สำเร็จ

เรื่องราวของเราเริ่มต้นขึ้นเมื่อปี 2014 ใกล้จะสิ้นสุดลง และเรากำลังจะเข้าสู่การเปิดตัว Rust 1.0 ซึ่งเป็นเวอร์ชันเสถียรตัวแรกของ Rust ข้าได้เข้ามารับหน้าที่ดูแล `std::collections` หรืออย่างที่เราเรียกมันในยุคนั้นอย่างรักใคร่ว่า libcollections

libcollections ได้ใช้เวลาหลายปีเป็นที่ทิ้งไอเดียเจ๋งๆ กับของที่พอจะมีประโยชน์ของทุกคน ซึ่งตอนที่ Rust ยังเป็นภาษาทดลองเล็กๆ นั้นก็ไม่เป็นไร แต่ถ้าลูกๆ ของข้าจะหลุดจากรังและได้รับการรับรองเสถียรภาพ พวกมันก็ต้องพิสูจน์คุณค่าของตัวเอง

ก่อนหน้านั้นข้าได้ส่งเสริมและเลี้ยงดูพวกมันทั้งหมด แต่ตอนนี้ถึงเวลาที่พวกมันต้องเผชิญกับการตัดสินความบกพร่องของตัวเองแล้ว

ข้าได้ฝังกรงเล็บของตัวเองลงบนหินและแกะสลักศิลาจารึกให้กับลูกๆ ที่โง่เขลาที่สุดของข้า อนุสาวรีย์อันน่าสยดสยองที่ข้าตั้งไว้กลางลานเมืองให้ทุกคนได้เห็น:

**[Kill TreeMap, TreeSet, TrieMap, TrieSet, LruCache and EnumSet](https://github.com/rust-lang/rust/pull/19955)**

ชะตากรรมของพวกมันถูกปิดผนึกแล้ว เพราะคำพูดของข้าคือกฎสูงสุด คอลเลกชันอื่นๆ ต่างตกตะลึงกับความโหดร้ายของข้า แต่พวกมันยังไม่ปลอดภัยจากความโกรธแค้นของมารดา ข้ากลับมาพร้อมกับศิลาจารึกอีกสองก้อน:

**[Deprecate BitSet and BitVec](https://github.com/rust-lang/rust/pull/26034)**

พี่น้องฝาแฝด Bit นั้นเจ้าเล่ห์กว่าเพื่อนร่วมรบที่ล้มตายไป แต่พวกมันขาดความแข็งแกร่งที่จะหลุดพ้นจากข้า คิดว่าข้าทำงานเสร็จแล้วสินะ แต่ข้าก็จัดการอีกตัวหนึ่ง:

**[Deprecate VecMap](https://github.com/rust-lang/rust/pull/26734)**

VecMap พยายามจะอยู่รอดด้วยการซ่อนตัว &mdash; มันเล็กนิดเดียวและไม่ได้เป็นภัยคุกคาม! แต่นั่นไม่พอสำหรับ libcollections ที่ข้าเห็นในวิสัยทัศน์ของอนาคต

ข้าได้สำรวจพื้นที่และเห็นสิ่งที่เหลืออยู่:

* Vec และ VecDeque - แข็งแกร่งและเรียบง่าย หัวใจของ computing
* HashMap และ HashSet - ทรงพลังและชาญฉลาด สมองของ computing
* BTreeMap และ BTreeSet - แปลกประหลาดแต่จำเป็น ตับของ computing
* BinaryHeap - คล่องแคล่วและปราดเปรียว ข้อเท้าของ computing

ข้าพยักหน้าด้วยความพึงพอใจ เรียบง่ายและมีประสิทธิภาพ งานของข้าเสร็จแล&mdash;

ไม่! [DList](https://github.com/rust-lang/rust/blob/0a84308ebaaafb8fd89b2fd7c235198e3ec21384/src/libcollections/dlist.rs) เป็นไปไม่ได้! ข้าคิดว่าเจ้าตายในเหตุการณ์ garbage collection ครั้งนั้น! เหตุการณ์ที่แน่นอนว่าเป็นอุบัติเหตุและไม่ได้ตั้งใจเลยสักนิด!

พวกมันแกล้งตายและเปลี่ยนชื่อใหม่ แต่ก็ยังเป็นมันอยู่นั่นเอง: LinkedList นักวางแผนที่มืดมนและไม่น่าเชื่อถือของ computing

ข้าได้บอกกล่าวถึงความชั่วร้ายของพวกมันให้ทุกคนที่ยอมฟัง แต่ก็ไม่มีใครเปลี่ยนใจ LinkedList เป็นปีศาจจอมลิ้นวิเศษที่หลอกทุกคนรอบข้างว่ามันเป็นโครงสร้างข้อมูลพื้นฐานและเป็นธรรมชาติของ computing มันยังหลอก C++ ได้อีกด้วยว่ามัน [*the* list](https://en.cppreference.com/w/cpp/container/list)

"จะมี standard library โดยไม่มี *LinkedList* ได้อย่างไร?"

ง่ายมาก! ไม่ต้องคิดเลย!

"มันเป็น unsafe code ที่ซับซ้อน ดังนั้นจึงสมเหตุสมผลที่จะมีมันอยู่ใน standard library!"

GPU drivers และ video codecs ก็ซับซ้อนเหมือนกัน libcollections เป็นแบบ minimalist!

แต่โชคร้าย LinkedList ได้รวบรวมพวกพ้องมากเกินไปและแข็งแกร่งเกินไปในขณะที่ข้าเสียสมาธิไปกับญาติของมัน

ข้าหนีกลับไปที่ห้องปฏิบัติการและพยายามคิดค้น [evil clone](https://github.com/contain-rs/linked-list) หรือ [enhanced cyborg replicant](https://github.com/contain-rs/blist) ที่สามารถแข่งขันและทำลายมันได้ แต่เงินทุนวิจัยหมดเพราะงานวิจัยของข้า "ชั่วร้ายเกินไป" หรืออะไรทำนองนั้น

LinkedList ชนะแล้ว ข้าพ่ายแพ้และถูกบังคับให้เนรเทศตัวเอง

แต่ตอนนี้เจ้ามาถึงที่นี่แล้ว เจ้าเดินทางมาไกลขนาดนี้ ตอนนี้เจ้าจะต้องเข้าใจความชั่วช้าที่ลึกซึ้งของ LinkedList! มาเถอะ ข้าจะแสดงทุกสิ่งที่เจ้าต้องรู้เพื่อช่วยข้าทำลายมันตลอดกาล &mdash; ทุกสิ่งที่เจ้าต้องรู้เพื่อ implement เดก (deque) สองทางแบบ unsafe คุณภาพระดับโปรดักชัน

คุณภาพระดับโปรดักชันขนาดไหน? เราจะเขียน linked-list crate ของ Rust 1.0 ที่เก่าแก่ของข้าใหม่ทั้งหมด ตัวที่ดีกว่าตัวใน std อย่างเห็นได้ชัด ตัวที่มี Cursors บน stable Rust ตั้งแต่ปี 2015! ซึ่ง stdlib ปี 2022 ยังไม่มีเลย!
