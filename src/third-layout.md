# โครงสร้างในหน่วยความจำ

เอาล่ะ กลับมาที่กระดานวาดภาพสำหรับโครงสร้าง

สิ่งที่สำคัญที่สุดเกี่ยวกับลิสต์แบบเพอร์ซิสเทนต์คือคุณสามารถจัดการหาง
ของลิสต์ได้ฟรีโดยพื้นฐาน:

ตัวอย่างเช่น นี่ไม่ใช่เวิร์กโหลดที่ไม่คุ้นเคยที่จะเห็นกับลิสต์แบบเพอร์ซิสเทนต์:

```text
list1 = A -> B -> C -> D
list2 = tail(list1) = B -> C -> D
list3 = push(list2, X) = X -> B -> C -> D
```

แต่ตอนท้ายเราต้องการให้หน่วยความจำดูแบบนี้:

```text
list1 -> A ---+
              |
              v
list2 ------> B -> C -> D
              ^
              |
list3 -> X ---+
```

สิ่งนี้ใช้ไม่ได้กับ Box เพราะความเป็นเจ้าของ `B` เป็น*ร่วม* ใครควรปลดปล่อยมัน?
ถ้าผม drop list2 มันจะปลดปล่อย B หรือเปล่า? ด้วย Box เราน่าจะคาดหวังแบบนั้น!

ภาษาเชิงฟังก์ชัน &mdash; และแทบทุกภาษาอื่น &mdash; รอดไปด้วย
การใช้*garbage collection* ด้วยเวทมนตร์ของ garbage collection B จะถูกปลดปล่อย
เฉพาะหลังจากทุกคนหยุดดูมัน ไชโย!

Rust ไม่มีอะไรเหมือน garbage collector ที่ภาษาเหล่านั้นมี
พวกมันมี GC แบบ*tracing* ซึ่งจะขุดผ่านหน่วยความจำทั้งหมดที่อยู่ในระบบ
ตอนรันไทม์และหาว่าอะไรเป็นขยะโดยอัตโนมัติ แทนที่จะทำแบบนั้น สิ่งที่
Rust มีในปัจจุบันคือ*การนับจำนวนอ้างอิง (reference counting)*
การนับจำนวนอ้างอิงสามารถคิดได้เป็น GC ที่ง่ายมาก สำหรับเวิร์กโหลดหลายชนิด
มันมี_throughput_น้อยกว่าตัวเก็บขยะแบบ tracing อย่างเห็นได้ชัด และมันจะ
ล้มเหลวทั้งหมดถ้าคุณสร้างวงจรได้ แต่เฮ้ นี่คือทั้งหมดที่เรามี! โชคดีที่สำหรับ
การใช้งานของเรา เราจะไม่มีวันเจอวงจร (ลองพิสูจน์ด้วยตนเองได้เลย &mdash; ผมไม่ทำแน่)

แล้วเราจะทำ garbage collection แบบนับจำนวนอ้างอิงยังไง? `Rc`! Rc เหมือน
Box แต่เราสามารถทำซ้ำมันได้ และหน่วยความจำของมันจะ*ถูกปลดปล่อยเฉพาะ*
เมื่อ Rc ที่*ทั้งหมด*ที่ได้มา ממנוถูก drop โชคร้ายที่ความยืดหยุ่นนี้มี
ค่าใช้จ่ายที่ร้ายแรง: เราสามารถรับแค่เรเฟอเรนซ์ร่วมกับอินเทอร์นัลของมัน นี่หมายความว่า
เราไม่สามารถเอาข้อมูลออกจากลิสต์ของเราได้จริง ๆ และเราไม่สามารถกลายพันธุ์มันได้เช่นกัน

แล้วโครงสร้างของเราจะดูยังไงล่ะ? ก่อนหน้านี้เรามี:

```rust ,ignore
pub struct List<T> {
    head: Link<T>,
}

type Link<T> = Option<Box<Node<T>>>;

struct Node<T> {
    elem: T,
    next: Link<T>,
}
```

เราเปลี่ยน Box เป็น Rc ได้เลยมั้ย?

```rust ,ignore
// in third.rs

pub struct List<T> {
    head: Link<T>,
}

type Link<T> = Option<Rc<Node<T>>>;

struct Node<T> {
    elem: T,
    next: Link<T>,
}
```

```text
cargo build

 --> src/third.rs:5:23
  |

  |                       ^^ not found in this scope

```

โอ้ ดับเบิลเบิร์น ต่างจากทุกอย่างที่เราใช้สำหรับลิสต์ที่กลายพันธุ์ได้ Rc
ห่วยจนมันไม่ได้ถูก import โดยปริยายในทุกโปรแกรม Rust *ขี้แพ้จริง ๆ*

```rust ,ignore
use std::rc::Rc;
```

ดูสมเหตุสมผล Rust ยังคงเขียนได้ง่าย*อย่างสมบูรณ์* ผมเดาว่าเราแค่
find-and-replace Box เป็น Rc แล้วเรียกวันจบได้เลย!
