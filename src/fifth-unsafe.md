# Unsafe Rust

นี่คือหัวข้อที่จริงจัง ยิ่งใหญ่ ซับซ้อน และอันตราย
มันจริงจังถึงขนาดที่ผมเคยเขียน[หนังสืออีกเล่มหนึ่งทั้งเล่ม][nom] เพื่ออธิบายเรื่องนี้โดยเฉพาะมาแล้ว

พูดให้สั้นและเข้าใจง่ายที่สุดก็คือ จริงๆ แล้ว*ทุก*ภาษาโปรแกรมบนโลกนี้ไม่ปลอดภัยทันทีที่คุณยอมให้มันเรียกข้ามไปทำงานกับภาษาอื่นได้ เพราะคุณสามารถสั่งให้ภาษา C ก่อเรื่องเลวร้ายพินาศสันตะโรแค่ไหนก็ได้ ใช่แล้วครับ: Java, Python, Ruby, Haskell... ทุกภาษานี้ล้วนตกอยู่ในสภาวะอันตรายถึงขีดสุดเมื่อต้องเผชิญหน้ากับ Foreign Function Interface (FFI)

Rust น้อมรับความจริงข้อนี้โดยแบ่งตัวเองออกเป็นสองภาษาในร่างเดียว: Safe Rust และ Unsafe Rust จนถึงตอนนี้เราเขียนกันแต่ Safe Rust มาโดยตลอด ซึ่งปลอดภัย 100% ไร้กังวล... ยกเว้นตรงที่มันสามารถ FFI มุดเข้าไปหา Unsafe Rust ได้นี่แหละ

Unsafe Rust เป็น *superset* ของ Safe Rust หมายความว่ามันมีกฎและ semantics ทุกอย่างเหมือนกับ Safe Rust เป๊ะๆ เพียงแต่คุณจะได้รับอภิสิทธิ์ให้ทำสิ่ง*พิเศษเพิ่มเติม*สองสามอย่างที่อันตรายสุดกู่ และสามารถนำพาเราไปพบกับสิ่งชั่วร้ายที่คอยตามหลอกหลอนโลกของ C อย่าง Undefined Behaviour ได้

ย้ำอีกทีว่านี่คือหัวข้อที่ใหญ่และมีเคสประหลาดๆ (corner cases) ที่น่าสนใจเพียบ ผม*ไม่อยาก*จะดำดิ่งลงไปลึกเกินไปในตอนนี้ (เอ่อ จริงๆ ก็อยากแหละ และทำไปแล้วด้วย [ลองไปอ่านเล่มนั้นดูสิ][nom]) แต่ไม่เป็นไรครับ เพราะการเขียน linked list เนี่ย เราแทบจะมองข้ามเรื่องพวกนั้นไปได้เกือบหมดเลย

> **ผู้บรรยาย:** นั่นเป็นคำโกหกทั้งเพ... แต่ย้อนกลับไปตอนปี 2015 มันก็ดูเหมือนจะเป็นความจริงอยู่หรอกนะ

อาวุธหลักในฝั่ง Unsafe ที่เราจะหยิบมาใช้กันก็คือ *raw pointer (พอยน์เตอร์ดิบ)* ซึ่งโดยพื้นฐานแล้วมันก็คือพอยน์เตอร์ของภาษา C นั่นเอง ตัวมันไม่มีกฎเรื่อง aliasing ผูกมัดในตัว, ไม่มี lifetime, สามารถเป็น null ได้, alignment เบี้ยวได้, เป็น dangling pointer ได้, ชี้ไปยังหน่วยความจำที่ยังไม่ได้ใส่ค่า (uninitialized memory) ได้, cast สลับไปมาระหว่างตัวเลขจำนวนเต็มได้, cast ข้ามไปชี้ type อื่นได้, อยากเปลี่ยนสถานะ mutability เหรอ? ก็ cast เอาสิ! แทบจะทำอะไรก็ได้ตามใจชอบทั้งนั้น และนั่นแปลว่า... ทุกสิ่งทุกอย่างก็พร้อมจะพังทลายลงมาได้ทุกเมื่อเช่นกัน

> **ผู้บรรยาย:** ไม่มีกฎ aliasing งั้นเรอะ? หึหึ... ช่างเป็นความไร้เดียงสาของคนหนุ่มสาวเสียจริง

เรื่องพวกนี้มันเลวร้ายมาก และถ้าพูดกันตรงๆ คุณจะมีชีวิตที่สงบสุขกว่านี้เยอะถ้าไม่ต้องไปแตะต้องมันเลย แต่อนิจจา เราดั้นด้นอยากจะมาเขียน linked list กันเอง และ linked list ใน Rust มันช่างโหดร้าย นั่นแปลว่าเราหลีกเลี่ยงไม่ได้ที่จะต้องใช้ unsafe pointer

raw pointer มีอยู่สองชนิดด้วยกัน: `*const T` และ `*mut T` ซึ่งตั้งใจสร้างมาเทียบเคียงกับ `const T*` และ `T*` ในภาษา C นั่นแหละ แต่เราไม่ได้แคร์ความหมายของ C ขนาดนั้นหรอก โดยปกติคุณจะ dereference จาก `*const T` ออกมาได้เป็น `&T` เท่านั้น แต่ก็คล้ายๆ กับ mutability ของตัวแปรทั่วไป มันทำหน้าที่เป็นแค่ตัวคอยเตือน (lint) กันไม่ให้ใช้งานผิดมากกว่า อย่างมากที่สุดมันก็แค่บังคับให้คุณต้อง cast จาก `*const` ไปเป็น `*mut` เสียก่อน ทว่า... ถ้าคุณไม่ได้มีสิทธิ์ในการแก้ไขค่าปลายทางของพอยน์เตอร์นั้นจริงๆ คุณได้เจอนรกแน่นอน

เอาเถอะ เดี๋ยวพอเราได้ลงมือเขียนโค้ดจริงๆ เราก็จะเริ่มจับทางมันได้เอง สำหรับตอนนี้ ท่องจำไว้ว่า:
`*mut T == &unchecked mut T`!
