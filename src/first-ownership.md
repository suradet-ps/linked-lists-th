# ความเป็นเจ้าของ 101

ตอนนี้เราสร้างลิสต์ขึ้นมาได้แล้ว มันคงจะดีไม่น้อยถ้าเราสามารถ *สั่งให้มันทำอะไรสักอย่าง* ได้ด้วย ซึ่งเราจะทำสิ่งนั้นผ่านเมธอด "ทั่วไป" (เมธอดที่ไม่ใช่สแตติก) ในภาษา Rust เมธอดถือเป็นกรณีพิเศษของฟังก์ชัน เนื่องจากมันมีพารามิเตอร์ `self` ซึ่งเป็นพารามิเตอร์ที่ไม่ต้องระบุชนิดข้อมูลกำกับไว้:

```rust ,ignore
fn foo(self, arg2: Type2) -> ReturnType {
    // body
}
```

รูปแบบหลัก ๆ ที่ `self` สามารถรับค่าได้มีอยู่ 3 แบบด้วยกัน ได้แก่: `self`, `&mut self`, และ `&self` โดยทั้งสามรูปแบบนี้เป็นตัวแทนของสามรูปแบบหลักในระบบความเป็นเจ้าของ (ownership) ของ Rust:

* `self` - ส่งผ่านด้วยค่า (Value)
* `&mut self` - เรเฟอเรนซ์ที่แก้ไขได้ (mutable reference)
* `&self` - เรเฟอเรนซ์แบบแชร์ (shared reference)

การรับแบบค่า (Value) หมายถึงความเป็นเจ้าของ *ที่แท้จริง* คุณมีสิทธิ์ขาดที่จะทำอะไรกับค่านั้นก็ได้: ย้ายมันไปที่อื่น, ทำลายมันทิ้ง, แก้ไขเปลี่ยนแปลงค่าของมัน หรือจะให้ตัวอื่นยืมผ่านเรเฟอเรนซ์ก็ย่อมได้ เมื่อคุณส่งผ่านข้อมูลแบบค่า ข้อมูลนั้นจะถูก *ย้าย (move)* ไปยังตำแหน่งใหม่ และตำแหน่งใหม่นั้นจะกลายเป็นเจ้าของข้อมูลทันที ส่วนตำแหน่งเดิมจะไม่สามารถเข้าถึงข้อมูลนั้นได้อีกต่อไป ด้วยเหตุนี้ เมธอดส่วนใหญ่จึงไม่ต้องการรับ `self` ตรง ๆ -- เพราะมันคงจะตลกพิลึก ถ้าการเรียกใช้งานลิสต์แค่ครั้งเดียว ทำให้ตัวแปรลิสต์นั้นอันตรธานหายวับไปกับตา!

เรเฟอเรนซ์ที่แก้ไขได้ (`&mut self`) หมายถึงสิทธิ์การ *เข้าถึงแบบเอกสิทธิ์ชั่วคราว (temporary exclusive access)* ต่อข้อมูลที่คุณไม่ได้เป็นเจ้าของ คุณมีสิทธิ์ทำอะไรก็ได้กับข้อมูลนั้นตราบใดที่คุณคืนมันกลับไปในสถานะที่ถูกต้องสมบูรณ์ (ไม่งั้นจะถือว่าเสียมารยาทกับเจ้าของเดิมแย่เลย!) ซึ่งหมายความว่าคุณสามารถเขียนทับข้อมูลนั้นใหม่ทั้งหมดได้เลยด้วยซ้ำ กรณีการใช้งานพิเศษที่มีประโยชน์มาก ๆ ของเรื่องนี้คือการ *สลับค่า (swap)* ข้อมูลตัวหนึ่งกับอีกตัวหนึ่ง ซึ่งเราจะได้ใช้บ่อยมาก สิ่งเดียวที่คุณทำไม่ได้กับ `&mut` คือการหยิบข้อมูลข้างในออกมาโดยไม่ใส่ข้อมูลใหม่กลับเข้าไปแทนที่ `&mut self` จึงเหมาะมากสำหรับเมธอดที่ต้องการแก้ไขเปลี่ยนแปลงข้อมูลใน `self`

เรเฟอเรนซ์แบบแชร์ (`&self`) หมายถึงสิทธิ์การ *เข้าถึงข้อมูลร่วมกันชั่วคราว (temporary shared access)* ต่อข้อมูลที่คุณไม่ได้เป็นเจ้าของ และเนื่องจากเป็นการเข้าถึงร่วมกับคนอื่น โดยทั่วไปคุณจึงไม่มีสิทธิ์เข้าไปแก้ไขค่าอะไรทั้งสิ้น ลองนึกภาพว่า `&` ก็เหมือนกับการนำสิ่งของไปตั้งโชว์ไว้ในพิพิธภัณฑ์ (ทุกคนเดินเข้ามาดูได้ แต่ห้ามแตะต้องแก้ไข) `&` จึงเหมาะอย่างยิ่งสำหรับเมธอดที่ต้องการเพียงแค่อ่านดูข้อมูลใน `self`

ในบทต่อ ๆ ไป เราจะได้เห็นว่ากฎเหล็กเรื่องห้ามแก้ไขข้อมูลนี้สามารถมีข้อยกเว้นได้ในบางกรณี นี่คือเหตุผลที่เรเฟอเรนซ์แบบแชร์ไม่ได้ถูกเรียกว่าเรเฟอเรนซ์ *แบบอิมมิวเทเบิล (immutable reference)* และในทำนองเดียวกัน เรเฟอเรนซ์ที่แก้ไขได้จริง ๆ แล้วอาจจะเรียกว่าเรเฟอเรนซ์ *แบบหนึ่งเดียว (unique reference)* เสียมากกว่า แต่เราพบว่าการผูกเรื่องความเป็นเจ้าของเข้ากับความสามารถในการแก้ไขค่า (mutability) ช่วยสร้างสัญชาตญาณความเข้าใจที่ถูกต้องได้ถึง 99% ของเวลาทั้งหมด
