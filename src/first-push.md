# Push (การเพิ่มเข้าหัว)

งั้นเรามาเริ่มเขียนโค้ดสำหรับเพิ่มข้อมูลใหม่เข้าไปในลิสต์กันเลย การทำงานของ `push` จำเป็นต้อง *แก้ไขเปลี่ยนแปลงค่า (mutate)* ในลิสต์ ดังนั้นเราจึงต้องรับพารามิเตอร์เป็น `&mut self` นอกจากนี้ เรายังต้องรับค่า `i32` ที่ต้องการเพิ่มเข้ามาอีกหนึ่งตัวด้วย:

```rust ,ignore
impl List {
    pub fn push(&mut self, elem: i32) {
        // TODO
    }
}
```

ลำดับแรกสุด เราจำเป็นต้องสร้างโหนดขึ้นมาเพื่อใช้เก็บข้อมูลของเรา:

```rust ,ignore
    pub fn push(&mut self, elem: i32) {
        let new_node = Node {
            elem: elem,
            next: ?????
        };
    }
```

แล้วอะไรควรจะไปอยู่ที่ฟิลด์ `next` ล่ะ? ก็ลิสต์เก่าทั้งหมดไง! แล้วเรา... แค่เขียนสั่งไปตรง ๆ แบบนี้ได้เลยไหมนะ?

```rust ,ignore
impl List {
    pub fn push(&mut self, elem: i32) {
        let new_node = Node {
            elem: elem,
            next: self.head,
        };
    }
}
```

```text
> cargo build
error[E0507]: cannot move out of borrowed content
  --> src/first.rs:19:19
   |
19 |             next: self.head,
   |                   ^^^^^^^^^ cannot move out of borrowed content
```

ไม่รอดดดด! สิ่งที่ Rust กำลังเตือนเราน่ะถูกต้องแล้ว แต่มันดันไม่ค่อยชัดเจนเท่าไหร่ว่าตกลงมันหมายความว่าอะไร และเราต้องแก้มันยังไง:

> cannot move out of borrowed content

ตรงนี้เรากำลังพยายามย้าย (move) ค่าในฟิลด์ `self.head` ออกไปใส่ใน `next` แต่ Rust ไม่อนุญาตให้เราทำแบบนั้น เพราะการทำเช่นนั้นจะทำให้ `self` ตกอยู่ในสถานะกึ่งสุกกึ่งดิบ (partially initialized) ในจังหวะที่เราจบการยืมและ "คืนของ" ให้กับเจ้าของที่แท้จริงของมัน ซึ่งอย่างที่เราบอกไปก่อนหน้านี้ นั่นคือ *สิ่งเดียว* ที่คุณห้ามทำเด็ดขาดเมื่อถือ `&mut`: เพราะมันจะถือว่าเสียมารยาทมาก และ Rust ก็เป็นภาษาที่สุภาพสุด ๆ (จริง ๆ แล้วมันอันตรายระดับคอขาดบาดตายเลยต่างหาก แต่นั่นคงไม่ใช่เหตุผลที่ Rust แคร์หรอกมั้ง หึหึ)

ถ้าอย่างนั้น ถ้าเราใส่ค่าอะไรสักอย่างกลับเข้าไปแทนที่ทันทีล่ะ? อย่างเช่น โหนดใหม่ที่เรากำลังสร้างอยู่นี่ไง:

```rust ,ignore
pub fn push(&mut self, elem: i32) {
    let new_node = Box::new(Node {
        elem: elem,
        next: self.head,
    });

    self.head = Link::More(new_node);
}
```

```text
> cargo build
error[E0507]: cannot move out of borrowed content
  --> src/first.rs:19:19
   |
19 |             next: self.head,
   |                   ^^^^^^^^^ cannot move out of borrowed content
```

ก็ยังไม่ผ่านอยู่ดี... ในทางทฤษฎีแล้ว นี่คือสิ่งที่คอมไพเลอร์น่าจะพอหยวน ๆ ยอมให้ผ่านได้ แต่ในความเป็นจริงมันไม่ยอม (ด้วยสารพัดเหตุผล ซึ่งข้อที่หนักหนาสาหัสที่สุดก็คือเรื่อง [ความปลอดภัยของข้อยกเว้น (exception safety)][exception safety]) เราจึงต้องหาวิธีฉกเอาหัวลิสต์ออกมา โดยไม่ให้ Rust รู้ตัวว่ามันหายไป! และสำหรับคำแนะนำในเรื่องนี้ เราคงต้องขอความช่วยเหลือจากแฮกเกอร์ Rust ในตำนานอย่าง อินเดียนา โจนส์ กันแล้วล่ะ:

![Indy Prepares to mem::replace](img/indy.gif)

ใช่แล้ว! คุณลุง Indy แนะนำให้ใช้กระบวนท่า `mem::replace` ฟังก์ชันที่มีประโยชน์อย่างเหลือเชื่อตัวนี้ ช่วยให้เราสามารถ "ขโมย" ค่าออกมาจากการยืม (borrow) ได้ โดยใช้วิธี *สลับเอาค่าอื่นเข้าไปแทนที่ทันที* งั้นเรามาสั่ง import `std::mem` ไว้ที่บนสุดของไฟล์ เพื่อดึง `mem` เข้ามาไว้ในสโคปกันก่อนเลย:

```rust ,ignore
use std::mem;
```

แล้วเรียกใช้งานมันอย่างถูกต้อง:

```rust ,ignore
pub fn push(&mut self, elem: i32) {
    let new_node = Box::new(Node {
        elem: elem,
        next: mem::replace(&mut self.head, Link::Empty),
    });

    self.head = Link::More(new_node);
}
```

ตรงนี้เราใช้ `replace` สลับค่าใน `self.head` ให้กลายเป็น `Link::Empty` ไปชั่วคราวก่อน (เหมือนตอน Indy เอาถุงทรายไปวางแทนเทวรูปทองคำ) แล้วค่อยเอาหัวใหม่ของลิสต์เข้าไปแทนที่อีกที ผมจะไม่โกหกหรอกนะ: การต้องมานั่งทำอะไรแบบนี้มันดูน่าเวทนาอยู่เหมือนกัน แต่ก็นั่นแหละ โชคร้ายที่เราจำเป็นต้องทำแบบนี้ไปก่อน (ในตอนนี้)

แต่เอาเถอะ เมธอด `push` ของเราก็เสร็จเรียบร้อยแล้ว! (คิดว่าน่าจะใช่นะ) ซึ่งเอาจริง ๆ เราก็ควรจะเทสต์มันหน่อย และวิธีที่ง่ายที่สุดตอนนี้ก็คือการเขียนเมธอด `pop` ขึ้นมา แล้วลองเช็กดูว่ามันให้ผลลัพธ์ถูกต้องตรงตามที่คิดไว้หรือเปล่า

[exception safety]: https://doc.rust-lang.org/nightly/nomicon/exception-safety.html
